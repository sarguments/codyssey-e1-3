# Mini NPU 시뮬레이터

숫자로 만든 패턴을 Cross(+)와 X 필터로 각각 계산하고, 더 높은 점수가 나온 모양을 찾는 Python 콘솔 프로그램

실제 NPU를 구동하는 대신 NPU에서 자주 쓰는 MAC 연산을 반복문으로 구현

## 동작 방식

컴퓨터가 모양을 계산할 수 있도록 Cross와 X를 숫자 배열로 표현

입력 패턴과 필터의 같은 자리 숫자를 곱한 뒤 전부 더해서 점수를 구하며, 이 과정을 MAC(Multiply-Accumulate) 연산이라고 부름

```text
입력 패턴
  ├─ Cross 필터와 MAC 계산 → Cross 점수
  └─ X 필터와 MAC 계산     → X 점수
                                ↓
                        두 점수의 차이 확인
                                ↓
                    Cross / X / UNDECIDED
                                ↓
                         expected와 비교
                                ↓
                          PASS / FAIL
```

두 점수 중 큰 쪽을 결과로 선택

차이가 `1e-9`보다 작으면 실수 계산에서 생긴 작은 오차로 보고 `UNDECIDED`로 처리

## 실행 방법

- Python 3.8 이상
- 외부 라이브러리 없이 Python 표준 라이브러리만 사용
- `main.py`와 `data.json`을 같은 폴더에 배치

```bash
python main.py
```

`python` 명령으로 실행되지 않으면 `python3 main.py` 사용

실행 후 `1` 또는 `2`를 입력해 모드 선택

| 선택 | 모드 | 하는 일 |
|---|---|---|
| `1` | 사용자 입력 | 직접 입력한 3×3 필터 A·B와 패턴을 계산 |
| `2` | `data.json` 분석 | 5×5, 13×13, 25×25 패턴을 한꺼번에 계산 |

### 사용자 입력 모드

필터 A, 필터 B, 패턴 순서로 입력

각 배열은 3줄이고 한 줄에는 숫자 3개를 공백으로 구분해 입력

행이나 열의 개수가 맞지 않거나 숫자가 아닌 값이 있으면 안내 문구를 출력하고 해당 배열을 처음부터 다시 입력

입력이 끝나면 A와 B의 MAC 점수, 10회 평균 연산 시간, 판정 결과를 출력

동점은 `판정 불가`로 표시

### JSON 분석 모드

`data.json`의 `filters`와 `patterns`를 읽고 `size_{N}_{idx}` 형식의 패턴 이름에서 크기 N을 확인

확인한 크기와 같은 Cross와 X 필터를 선택

각 케이스의 점수, 판정, expected, PASS/FAIL을 출력

잘못된 데이터는 해당 케이스만 FAIL로 처리하고 다음 케이스를 계속 분석

동점은 `UNDECIDED`로 표시

## 구현 흐름

JSON 케이스 하나를 처리하는 순서

```text
패턴 이름과 필수 값 확인
→ 라벨을 Cross/X로 통일
→ 패턴과 필터의 크기·숫자 확인
→ Cross/X MAC 점수 계산
→ epsilon 기준으로 판정
→ expected와 비교해 PASS/FAIL 결정
```

| 단계 | 구현 내용 |
|---|---|
| 입력 확인 | 패턴 이름, `input`, `expected`, 크기별 필터가 있는지 확인 |
| 라벨 통일 | expected의 `+`와 필터 키 `cross`를 `Cross`로, `x`를 `X`로 변환 |
| 배열 확인 | 패턴과 필터가 N×N인지, 모든 값이 숫자인지 확인 |
| MAC 계산 | 같은 위치의 값을 곱하고 중첩 반복문으로 모두 더함 |
| 점수 비교 | 점수 차이가 `1e-9`보다 작으면 `UNDECIDED`로 판정 |
| 실패 처리 | 잘못된 케이스의 원인을 기록하고 다음 케이스를 계속 처리 |
| 성능 측정 | 입력과 출력을 제외하고 MAC 함수만 10회 실행해 평균 계산 |

라벨은 원문에서 허용한 값만 변경

`+`와 `cross`는 `Cross`로, `x`는 `X`로 바꾸지만 `croos` 같은 오타는 그대로 오류 처리

## 결과 리포트

- 실행 환경: macOS Darwin 24.6.0 x86_64, Python 3.12.13
- 분석 대상: `data.json`의 6개 패턴
- 통과: 3개
- 실패: 3개

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9000000000000000 | 0.8999999999999999 | `UNDECIDED` | `X` | FAIL |
| `size_5_2` | 8.9000000000000004 | 0.1000000000000000 | `Cross` | `Cross` | PASS |
| `size_13_1` | 0.3000000000000000 | 14.7000000000000082 | `X` | `X` | PASS |
| `size_13_2` | 7.4999999999999973 | 7.5000000000000000 | `UNDECIDED` | `Cross` | FAIL |
| `size_25_1` | 4.9000000000000004 | 4.8999999999999986 | `UNDECIDED` | `X` | FAIL |
| `size_25_2` | 52.8999999999999986 | 0.1000000000000000 | `Cross` | `Cross` | PASS |

### FAIL 케이스 원인

| 케이스 | 두 점수의 차이 | FAIL 원인 |
|---|---:|---|
| `size_5_1` | 약 `1.11e-16` | 두 점수가 사실상 같아 `UNDECIDED`이지만 expected는 `X` |
| `size_13_2` | 약 `2.66e-15` | 두 점수가 사실상 같아 `UNDECIDED`이지만 expected는 `Cross` |
| `size_25_1` | 약 `1.78e-15` | 두 점수가 사실상 같아 `UNDECIDED`이지만 expected는 `X` |

FAIL 3개는 MAC 계산 오류가 아니라 epsilon 기준으로 생긴 결과

세 케이스 모두 두 점수의 차이가 `1e-9`보다 작아 `UNDECIDED`로 판정

expected에는 Cross 또는 X만 들어 있으므로 `UNDECIDED`와 일치하지 않아 FAIL 처리

### 성능 측정 결과

입력, 출력, 파일 읽기 시간을 빼고 MAC 함수만 10회 실행한 평균

3×3은 미션의 Cross 예제를 사용하고 나머지는 `data.json`의 첫 번째 패턴과 Cross 필터를 사용

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|---|---:|---:|
| 3×3 | 0.002173 | 9 |
| 5×5 | 0.004444 | 25 |
| 13×13 | 0.023309 | 169 |
| 25×25 | 0.079619 | 625 |

### 결과 해석

- `data.json`의 패턴 6개를 모두 분석
- 판정과 expected가 같은 3개 케이스는 PASS
- `UNDECIDED`로 판정된 3개 케이스는 FAIL
- `+`, `cross`, `x`를 Cross와 X로 통일해 표기 차이로 생긴 FAIL은 없음
- `size_5_1`의 점수 차이는 약 `1.11e-16`으로 epsilon보다 작음
- `size_13_2`의 점수 차이는 약 `2.66e-15`로 epsilon보다 작음
- `size_25_1`의 점수 차이는 약 `1.78e-15`로 epsilon보다 작음
- N×N 배열에는 N²개의 값이 있어 MAC의 시간 복잡도는 `O(N²)`
- 측정 시간도 3×3에서 25×25로 커질수록 증가
- 한 번의 측정값은 차이가 날 수 있어 각 크기를 10회 실행한 평균 사용

## 더 큰 행렬과 NPU

1000×1000 배열에는 100만 개의 값이 있고 패턴 하나와 필터 두 개를 함께 저장하면 최소 300만 개의 값을 다뤄야 함

현재 프로그램은 `json.load()`로 파일 전체를 읽기 때문에 데이터가 커지면 메모리 사용량도 늘어남

메모리를 줄이려면 데이터를 케이스나 행 묶음으로 나눠 읽고 계산이 끝난 데이터는 정리하는 방식이 필요

현재 코드는 Python 반복문으로 MAC을 차례대로 계산하지만 실제 NPU는 여러 곱셈을 동시에 처리하는 데 강함

3×3처럼 작은 배열은 NPU로 데이터를 보내고 준비하는 시간이 더 걸릴 수 있어 CPU가 더 알맞을 수 있음
