# Mini NPU 시뮬레이터

입력 패턴을 Cross 또는 X 필터와 MAC(Multiply-Accumulate) 연산으로 비교하는 Python 콘솔 프로그램입니다. 사용자가 직접 3×3 배열을 입력하는 모드와 `data.json`의 여러 케이스를 분석하는 모드가 있습니다.

## 실행 방법

- Python 3.8 이상
- `main.py`와 `data.json`을 같은 폴더에 둔 상태에서 실행

```bash
python main.py
```

`python` 명령어가 Python 3를 가리키지 않는 환경에서는 `python3 main.py`를 사용합니다. 프로그램을 실행한 뒤 `1`을 입력하면 사용자 입력 모드, `2`를 입력하면 `data.json` 분석 모드가 실행됩니다.

### 사용자 입력 모드

필터 A, 필터 B, 패턴 순서로 각각 3줄을 입력합니다. 한 줄에는 숫자 3개를 공백으로 구분합니다. 열 개수가 다르거나 숫자가 아닌 값이 있으면 해당 배열을 처음부터 다시 입력받습니다.
입력이 끝나면 A/B 점수, 10회 MAC 평균 연산 시간과 A/B/판정 불가 결과를 출력합니다.

### JSON 분석 모드

`main.py`와 같은 폴더의 `data.json`에서 `filters`와 `patterns`를 읽습니다. 패턴 키 `size_{N}_{idx}`에서 크기를 추출해 같은 크기의 필터를 선택하고, 케이스마다 점수·판정·expected·PASS/FAIL을 출력합니다. 잘못된 케이스는 실패 원인을 남기고 다음 케이스를 계속 처리합니다.

## 구현 요약

| 항목 | 구현 내용 |
|---|---|
| JSON 스키마 검증 | 최상위 `filters`/`patterns`, 케이스의 `input`/`expected`, 크기별 Cross/X 필터를 단계별로 확인 |
| 배열 검증 | 패턴 키의 N을 기준으로 패턴과 Cross/X 필터의 행·열 수와 모든 원소의 숫자 여부를 확인 |
| 라벨 정규화 | expected의 `+`와 필터 키 `cross`를 `Cross`로, `x`를 `X`로 통일 |
| MAC 연산 | 중첩 반복문으로 같은 위치의 값을 곱해 누적 |
| 점수 비교 | 점수 차이가 `1e-9`보다 작으면 `UNDECIDED` 처리 |
| 실패 격리 | 크기·숫자·라벨·키 오류를 케이스 단위 FAIL로 처리하고 구체적인 원인을 저장 |
| 성능 측정 | MAC 호출 직전과 직후만 10회 측정해 평균 밀리초 계산 |

## 결과 리포트

- 실행 환경: macOS Darwin 24.6.0 x86_64, Python 3.12.13
- 분석 대상: `data.json`의 6개 패턴
- 통과: 3개
- 실패: 3개

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9000000000000000 | 0.8999999999999999 | `UNDECIDED` | `X` | FAIL |
| `size_5_2` | 8.9000000000000004 | 0.1000000000000000 | `Cross` | `Cross` | PASS |
| `size_13_1` | 0.3000000000000000 | 14.7000000000000082 | `X` | `X` | PASS |
| `size_13_2` | 7.4999999999999973 | 7.5000000000000000 | `UNDECIDED` | `Cross` | FAIL |
| `size_25_1` | 4.9000000000000004 | 4.8999999999999986 | `UNDECIDED` | `X` | FAIL |
| `size_25_2` | 52.8999999999999986 | 0.1000000000000000 | `Cross` | `Cross` | PASS |

### FAIL 케이스 원인 분석

| FAIL 케이스 | 점수 차이 | FAIL 원인 |
|---|---:|---|
| `size_5_1` | 약 `1.11e-16` | 차이가 epsilon보다 작아 `UNDECIDED`이지만 expected는 `X` |
| `size_13_2` | 약 `2.66e-15` | 차이가 epsilon보다 작아 `UNDECIDED`이지만 expected는 `Cross` |
| `size_25_1` | 약 `1.78e-15` | 차이가 epsilon보다 작아 `UNDECIDED`이지만 expected는 `X` |

### 성능 표 및 해석

각 크기에서 MAC 연산만 10회 실행한 평균입니다. 3×3은 내장 Cross 예제를, 나머지는 `data.json`의 첫 번째 패턴과 Cross 필터를 사용했습니다.

| 크기 | 평균 시간(ms) | 연산 횟수 |
|---|---:|---:|
| 3×3 | 0.002173 | 9 |
| 5×5 | 0.004444 | 25 |
| 13×13 | 0.023309 | 169 |
| 25×25 | 0.079619 | 625 |

### 분석 요약

1. `data.json`의 전체 패턴은 6개이며, 실행 결과는 PASS 3개와 FAIL 3개입니다.
2. `size_5_2`, `size_13_1`, `size_25_2`는 판정과 정규화된 expected가 같아 PASS입니다.
3. expected의 `+`는 `Cross`로, `x`는 `X`로 변환되므로 표기 방식이 달라서 발생하는 FAIL은 없습니다.
4. `size_5_1`은 점수 차이가 약 `1.11e-16`이므로 epsilon 정책에 따라 `UNDECIDED`로 판정됩니다.
5. `size_13_2`는 점수 차이가 약 `2.66e-15`이므로 epsilon 정책에 따라 `UNDECIDED`로 판정됩니다.
6. `size_25_1`은 점수 차이가 약 `1.78e-15`이므로 epsilon 정책에 따라 `UNDECIDED`로 판정됩니다.
7. 위 세 케이스의 expected는 `Cross` 또는 `X`이므로 `UNDECIDED`와 일치하지 않아 FAIL이 됩니다.
8. N×N MAC은 모든 위치에서 곱셈과 누적을 한 번씩 수행하므로 연산 횟수는 N²입니다.
9. 입력 크기가 3, 5, 13, 25로 커질 때 연산 횟수는 9, 25, 169, 625로 증가합니다.
10. 반복문이 N개의 행과 N개의 열을 방문하므로 MAC의 시간복잡도는 `O(N²)`입니다.
11. 측정된 평균 시간도 크기가 커질수록 전반적으로 증가하여 N² 연산량과 같은 경향을 보입니다.
12. 단발 측정의 타이머 오차를 줄이기 위해 각 크기별 MAC을 10회 실행한 평균 시간을 사용했습니다.
